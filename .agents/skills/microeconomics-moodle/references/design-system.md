# Единый шаблон оформления Moodle HTML

Версия стандарта: 1.0.

## Назначение и приоритет
Единый обязательный визуальный стандарт для HTML-страниц семинаров 1–11. Применять при каждом создании или изменении оформления. Обычные информационные страницы и инструкции курса используют те же компоненты. Смысловую структуру страницы задаёт навык Moodle; этот файл определяет только её внешний вид.

Основа — согласованный шаблон Seminarul 2. Существующие различия других файлов не являются новыми образцами. При расхождении старого файла с этим стандартом использовать стандарт. Специальное оформление копируемого вопроса Realtime Quiz задаётся навыком интерактивных тестов и имеет приоритет для этого компонента.

Требования определяются здесь один раз. Не создавать отдельные наборы шрифтов, отступов и карточек для разных семинаров. Значения цветов брать по именам ролей из [единой палитры](../../microeconomics-seminar/references/course-resources.md), не дублировать здесь цветовые коды. Новое изменение общего оформления вносить сначала в этот файл и затем согласованно применять ко всем затронутым страницам.

Основной текст выравнивать по левому краю. Не растягивать по ширине. Жирным выделять понятие, результат или ключевую связь, а не весь абзац. Формулы, таблицы и графики могут использовать полную ширину карточки. Длинные заголовки естественно переносятся; фиксированная высота для них не задаётся.

## Шапка
Один компактный компонент из двух строк: небольшая метка «Microeconomie · ASEM» и единый h1 «Seminarul N — Titlul temei». На узком экране заголовок естественно переносится.

Фон — градиент основных заголовков и вторичного синего; текст белый. Внутренние поля 16 px по вертикали и 20 px по горизонтали. Радиус 12 px. Нижний отступ 24 px. Метка курса по шкале служебного текста: прописные буквы с разрядкой 1.2 px. Между меткой и заголовком 6 px. У h1 margin:0; фиксированной высоты нет. При наличии старых media-правил h1 использовать inline font-size:24px!important, чтобы шапка сохраняла единый размер и на телефоне.

Готовая разметка компонента: [compact-header.html](../assets/compact-header.html). Подставлять номер и HTML-экранированное название темы; повторяющиеся новые варианты компонента не создавать.

Компактная шапка утверждена пользователем. Применять одинаковый компонент во всех HTML семинаров, чтобы освободить место для учебного текста.

## Оглавление и переходы внутри страницы
Для длинной страницы предусматривать один общий компактный блок переходов к существующим основным разделам. Он находится после вводной части перед учебными разделами. Пункты — короткие текстовые ссылки с переносом строк и интервалами из общей сетки. Не создавать разные меню для каждого семинара и не добавлять содержательные разделы ради меню.

Использовать якоря существующих заголовков. Ссылка «Înapoi la cuprins» оформляется одинаково в конце длинного раздела. Набор пунктов соответствует фактической странице. Внешняя навигация курса остаётся внизу согласно навыку Moodle.

## Карточки и смысловые блоки

Общая геометрия: ширина 100%, box-sizing:border-box, фон карточки из палитры, рамка 1 px, радиус 12 px, внутренние поля 20 px по вертикали и 22 px по горизонтали. Без фиксированной высоты. Тяжёлые тени не используются.

| Назначение | Оформление |
| --- | --- |
| Теория и определение | Нейтральная карточка; тёмный текст; заголовок по иерархии |
| Данные и условие задачи | Белая карточка; отчётливо отделённые внутренние блоки |
| Разобранный пример | Общая карточка задачи; шаги решения разделены отступами |
| Экономический вывод или правильный ответ | Светлая зелёная поверхность; левая полоса 5 px цвета вывода |
| Практическая иллюстрация | Нейтральная светло-серая поверхность |
| Важное предупреждение | Светлая нейтральная поверхность и текстовая метка Atenție |
| Интерактивная модель | Общая карточка с подписью, графиком и отдельной группой управления |

Точные названия и порядок учебных блоков определены в справочнике паттернов задач. Не заменять этот порядок декоративной компоновкой. Не выделять каждое предложение отдельной карточкой.

Основной текст сохраняет тёмный цвет. Цвета спроса, предложения и равновесия прежде всего используются для обозначений, графиков, маркеров и небольших акцентов. Цвет сопровождается словесной подписью, чтобы смысл не зависел от одного цвета.

## Формулы
Общий размер формулы соответствует основному тексту. Ключевую формулу можно выделить полужирным в нейтральном блоке с полями 12 px по вертикали и 16 px по горизонтали. Расшифровка обозначений и единицы находятся рядом.

Сохранять типографические индексы и математические знаки. Не превращать формулу в картинку ради оформления. Если формула не помещается, разбивать по математически допустимым местам либо помещать в локально прокручиваемый контейнер. Не уменьшать её до нечитаемого размера.

## Таблицы
Таблица имеет настоящий табличный HTML: caption при необходимости, th для заголовков, td для данных. Общий размер текста задан типографической шкалой. Поля ячейки 12 px по вертикали и 14 px по горизонтали; рамки 1 px цвета рамок. Шапка светло-серая с полужирным текстом. Текстовые колонки выравнивать слева; однородные числовые значения — справа; единицы в заголовках.

Каждую широкую таблицу помещать в собственный контейнер width:100%; max-width:100%; overflow-x:auto. Минимальная ширина допустима только у внутренней таблицы, если необходима для её чтения. Не задавать min-width всем таблицам страницы глобально и не расширять корневой контейнер.

Сохранение исходной структуры и значений определяется общими правилами. Строки не обрезать, колонки не удалять и данные не заменять изображением ради узкого экрана.

## Графики и схемы
SVG имеет viewBox и адаптивные width:100%; max-width:100%; height:auto. Корректное соотношение сторон сохраняется. Подписи осей, величин, линий и единиц читаемы; размер не ниже размера подписей из типографической шкалы. Экономическая геометрия неизменна.

Перед графиком — короткий заголовок, под ним — понятная интерпретация. Легенда одинакового вида; линия отличается также подписью или рисунком штриха. Если уменьшение делает подписи нечитаемыми, использовать локальную прокрутку или отдельную увеличенную область, а не расширять страницу. Поведение модели определяется навыком Moodle.

## Кнопки, поля и раскрытие
- Минимальная высота активного элемента 44 px. Поля кнопки 10 px по вертикали и 16 px по горизонтали; радиус 8 px. Текст по общей шкале.
- Главное действие — фон основного заголовка и белый текст. Вторичное — белый фон, тёмный текст, рамка. Ссылки обозначаются как ссылки, а не скрываются под обычным текстом.
- Кнопки одной группы имеют одинаковые размеры, выравнивание и перенос на новую строку. Не использовать только иконку без понятной подписи.
- У клавиатурного фокуса видимая рамка минимум 3 px. Disabled-состояние отличается визуально и не выполняет переход.
- Подпись поля, текущее значение и единица находятся рядом. Ползунок имеет видимую подпись; значения не сообщаются одним цветом.
- Details оформляется общей рамкой и радиусом карточки. Summary: 18 px, полужирный, поля 14 px по вертикали и 16 px по горизонтали. Между соседними блоками 12 px. Нативный признак раскрытия виден. Кнопки управления раскрытием имеют общий вид остальных кнопок.

Названия кнопок и область доступных ответов заданы предметными навыками; здесь не создаётся другая редакция учебных правил.

## Нижняя навигация
Предыдущий семинар, список семинаров и следующий семинар образуют одну группу. Все элементы используют общую геометрию ссылок-кнопок, промежуток 8 px, естественный перенос на узком экране. Блок отделён от материалов отступом 32 px. Реальные адреса и состояние неизвестных переходов регулируются навыком Moodle.

## Устойчивость в Moodle и на телефоне
Важные размеры, фоны, рамки, цвет и интервалы задаются inline на самих элементах. Корневой div наследует основную гарнитуру и текст. Style и media queries могут улучшать отображение, но не являются единственным источником оформления.

Использовать гибкие блоки с переносом, а не жёсткие многоколоночные ширины. Для прямой вставки в Moodle сохранять читаемую одноколоночную основу. Не прятать условия задач или таблицы только ради мобильного вида. Горизонтальная прокрутка допускается внутри конкретной таблицы/модели, а не всей страницы.

## Проверка применения стандарта
1. Открыть все затронутые страницы при ширине 320, 390, 768 и 1150 px.
2. У всей страницы scrollWidth не превышает ширину области просмотра. Длинный заголовок, раскрытый ответ, таблица и график не ломают страницу.
3. Сравнить одноимённые компоненты разных семинаров: шапку, h2/h3, условие, решение, вывод, таблицу, график и навигацию.
4. Проверить клавиатурный фокус, кликабельность, раскрытие, контраст и читаемость. Для обычного текста ориентир контраста 4.5:1; недостаточно контрастные яркие цвета использовать как акценты с тёмным текстом.
5. Для прямой вставки сохранить и повторно открыть страницу Moodle. Локальная проверка и проверка после редактора фиксируются отдельно.
