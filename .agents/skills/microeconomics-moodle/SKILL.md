# Moodle

Общие требования заданы в [общем навыке](../microeconomics-seminar/SKILL.md). Для задач прочитать [единые паттерны](../microeconomics-seminar/references/problem-patterns.md). Имена образцов и URL находятся в [реестре](../microeconomics-seminar/references/course-resources.md).

## Учебная страница
1. Прочитать текущую страницу и сохранить стиль образца Seminarul 2. Имя в основной папке семинара: NN_Seminarul_N_Moodle.html; NN — двузначный номер. Именование копий для загрузки определено в общем навыке.
2. Начало: Microeconomie · ASEM → Seminarul N → Titlul seminarului → Descrierea seminarului.
3. Основные разделы строго:
   - 1. Obiectivele seminarului.
   - 2. Bazele teoretice ale seminarului.
   - 3. Formule principale și algoritmi.
   - 4. Exemple de probleme rezolvate în cadrul seminarului.
   - 5. Probleme pentru rezolvare.
4. Не подменять названия разделов 4–5 случайными вариантами. Не помещать под ними служебный текст о количестве созданных аналогов или процессе проверки. Допустима одна короткая учебная вводная фраза.
5. После них сохранять разрешённые проверочные блоки, реально имеющиеся в источнике. Не добавлять отсутствующие блоки ради одинакового количества разделов.
6. Предпоследний содержательный раздел — Concluzii esențiale. Последний — Materiale seminarului, с очередным последовательным номером, а не обязательно 6. В нём только ссылка скачивания финальной презентации текущего семинара. Подтвердить файл и download URL; не подменять ссылкой редактора. Если URL неизвестен, сохранить заголовок и пустое содержимое без кнопки или обещания добавить позже.
7. Не включать в этот раздел Curriculum, учебники, исходные PDF, Baza temei, Suport de curs и рабочие файлы. Доступ к приватной презентации не менять автоматически.
8. Решённые и студенческие задачи оформлять соответствующей ветвью единого паттерна; при изменении задач выполнить синхронизацию по навыку конспектов/решений.

## Исходные проверочные блоки
- Сохранять структуру проверочного блока и порядок вопросов и вариантов. Внутренняя нумерация исходника не меняется при перенумерации разделов.
- Простую геометрию можно перерисовать в SVG без изменения смысла; текстовое описание не заменяет рисунок.
- Для Întrebări de verificare дать содержательные ответы; для Adevărat/Fals — оценку и объяснение; для Teste grilă — правильный вариант или несколько вариантов с объяснением. Не навязывать единственную букву, если исходник допускает несколько.
- Ответы для самопроверки оформлять зелёными раскрывающимися блоками Vezi răspunsul și explicația. Это не распространяется на раздел 5.
- Требование менять соседние правильные буквы относится только к адаптированному интерактивному тесту.

## Интерактив и раскрытие
- Графики: HTML + SVG + JavaScript без внешних библиотек по умолчанию. Интерактив ставить сразу после объясняемой теории.
- Значения равновесия, оптимума, касания, |E|=1 и другие ключевые точки должны достигаться точно. При необходимости добавить кнопку точной установки. Можно сохранять отметку опорной точки при движении текущей.
- Раскрывающиеся блоки: нативные details/summary. Кнопки строго Deschide toate и Închide toate.
- После редактирования проверить сохранность SVG, функций, обработчиков, всех состояний и подписей.

## Прямая вставка в Moodle/TinyMCE
Эта процедура применяется к информационным HTML-полям, включая инструкцию индивидуальной работы.
- Открыть утверждённый образец из реестра. Вставлять содержимое одного корневого div, без зависимости от оболочки html/head/body.
- Каждому важному контейнеру, заголовку, карточке, тексту и ссылке задать собственный style. Не полагаться только на классы, style в head, внешний CSS или media queries.
- Для обычного раскрытия использовать нативные вложенные details/summary. Не добавлять script или JS-аккордеон там, где нужна только навигация.
- Настоящие ссылки a href отвечают за переход и скачивание. Следить за узкой колонкой, телефоном, переносом длинных названий и отсутствием горизонтального переполнения.
- После вставки сохранить и заново открыть именно Moodle-страницу. При удалении стилей редактором адаптировать и проверить снова. Полноценный автономный HTML и специальные учебные интерактивы остаются отдельными форматами; их работу в Moodle проверять отдельно.

## Навигация
- После материалов: предыдущий N−1 → Toate seminarele → следующий N+1. В HTML нет искусственной печатной пагинации.
- Использовать абсолютные подтверждённые Moodle URL из единого реестра. Сверить курс, подпись, тему и обе стороны соседней пары переходов.
- Не подставлять Drive или локальный HTML вместо страницы Moodle и не угадывать ID. Неизвестный следующий переход сделать неактивным.
- При авторизованном доступе открыть конечные страницы. Если это невозможно, отдельно сообщить предел проверки.
