# Языковая проверка

Применить общие языковые требования из [общего навыка](../microeconomics-seminar/SKILL.md); не определять здесь вторую редакцию этих требований.

1. Исходный код LanguageTool подключён в third-party/languagetool. Для проверки нужен отвечающий сервер либо выполненная офлайн-проверка через CLI готового дистрибутива. Обе процедуры описаны в docs/languagetool.md от корня проекта. Конфигурация или наличие исходников сами по себе не подтверждают работу.
2. Из корня проекта выполнить:
   python tools/check_course_text.py "путь/NN_Seminarul_N_Moodle.html" --language ro --output reports/seminar-N-language.json
3. По умолчанию используется локальный сервер 127.0.0.1:8081. Другой --server — явный выбор пользователя.
4. Команда читает оригиналы и создаёт отчёт, не применяя исправления. Языковые замечания и дополнительные проверки курса разделены. Предложения рассматривать вручную с учётом требований к источнику, терминов и общих правил.
5. HTML: извлекается статический текст без script/style/head/template/textarea. Динамические строки и текст изображений требуют отдельного просмотра. DOCX/PPTX: только нативный текст. PDF: текстовый слой с pdftotext; сканы и слайды-картинки требуют OCR и визуальной сверки.
6. Код 0 — замечаний нет; 1 — есть замечания для просмотра; 2 — проверка не выполнена. Смещения LanguageTool внутри фрагмента — UTF-16; chunk_start_codepoints — символы извлечённого текста. Это не позиции исходного HTML.
7. Проверка языка не доказывает экономическую корректность, правильность вычислений, источников и визуальной модели. Не объявлять проверку выполненной при ошибке выбранного способа. При запрете локальных сокетов использовать CLI без запуска сервера.

## Офлайн-проверка без HTTP

Извлечь видимый текст HTML с разделением блочных элементов пробелами или переносами строк. Удалить script/style/head. Передать UTF-8 файл локальному дистрибутиву:

```bash
java -Xmx384m -jar /path/to/LanguageTool-6.6/languagetool-commandline.jar -l ro -c utf-8 --json seminar.txt > report.json
```

Успешное выполнение команды и корректный JSON подтверждают запуск проверки. Замечания требуют ручного разбора; неизвестные формулы и экономические сокращения часто дают ложные срабатывания. Код CLI не использовать как автоматический признак отсутствия замечаний. В отчёте указать версию, язык, перечень проверенных файлов и ограничения извлечения.
