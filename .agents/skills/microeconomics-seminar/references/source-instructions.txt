0.17. ГЛАВНОЕ ПРАВИЛО ОБОЗНАЧЕНИЙ — ОБЯЗАТЕЛЬНО ДЛЯ ВСЕХ СЕМИНАРОВ.


Основной экономический символ пишется ПРОПИСНОЙ буквой обычного размера.
Все буквенные индексы при нём пишутся строчными буквами уменьшенного размера — снизу или сверху в зависимости от экономического смысла.


Примеры правильного отображения в Moodle HTML:
- Q<sub>d</sub> — cantitatea cerută;
- Q<sub>s</sub> — cantitatea oferită;
- Q<sub>d,a</sub> — cantitatea cerută din bunul A;
- P<sub>a</sub>, P<sub>b</sub>, P<sub>x</sub>, P<sub>y</sub> — prețurile bunurilor;
- E<sup>p</sup><sub>d</sub> — elasticitatea cererii față de preț;
- E<sup>p</sup><sub>s</sub> — elasticitatea ofertei față de preț;
- E<sub>i</sub> — elasticitatea cererii față de venit;
- E<sub>xy</sub> — elasticitatea încrucișată;
- ΔQ<sub>d</sub>%, ΔP<sub>x</sub>% — modificări procentuale;
- MU<sub>x</sub>/P<sub>x</sub> = MU<sub>y</sub>/P<sub>y</sub>;
- panta liniei bugetare: −P<sub>x</sub>/P<sub>y</sub>.


REGULA VIZUALĂ:
- Q, P, E, MU, TU, CO etc. = simbolul principal, mare;
- d, s, a, b, x, y, i, xy, p etc. = indice, mic și cu literă minusculă;
- dacă indicele este superior, el rămâne tot minuscul: E<sup>p</sup><sub>d</sub>, nu E<sup>p</sup><sub>d</sub>.


Este interzis să se folosească simbolul _ pentru a imita indicii în textul vizibil pentru student.
Pentru Moodle HTML se folosesc <sub> și <sup>.
Pentru DOCX, PDF și PPTX se folosesc indicii tipografici reali.
În JavaScript, HTML id și alte denumiri tehnice, _ este permis numai dacă nu este afișat studentului.


După orice generare sau editare a unui seminar se verifică toate formulele, tabelele, etichetele graficelor și textele generate dinamic pentru respectarea acestei reguli.

======================================================================
6. СТИЛЬ ОБЪЯСНЕНИЯ ТЕОРИИ
======================================================================


Материал должен быть академически правильным, но максимально понятным.


Порядок объяснения:
1. Что происходит экономически?
2. Почему это происходит?
3. Что означает каждое новое понятие, сокращение и символ?
4. Как это выражается формулой?
5. Короткий числовой пример.
6. Экономическая интерпретация результата.


Важное понятие желательно объяснять по схеме:
Definiție → Simboluri / abrevieri explicate → Formulă / relație → Exemplu → Calcul → Rezultat → Interpretare economică.


Формула должна находиться рядом с понятием, которое она объясняет, а не в отдельном бессвязном «складе формул».


Готовые материалы пишутся преимущественно на ROMÂNĂ с корректными диакритическими знаками.

8. РЕШЁННЫЕ ЗАДАЧИ
======================================================================


Перед решением проверить по источнику:
- номер;
- условие;
- коэффициенты;
- функцию;
- единицы;
- таблицу;
- график;
- что именно требуется определить.


Стандарт:
Datele problemei
→ Determinați
→ Ideea economică
→ Pasul 1 — Ce facem și de ce
→ calcul
→ Pasul 2 — Ce facem și de ce
→ calcul
→ ...
→ rezultat
→ Tabel completat / grafic completat, если нужен
→ Concluzie economică
→ Exemplu practic


Каждый шаг должен объяснять:
- что вычисляется;
- зачем применяется формула;
- откуда взялось каждое число;
- что означает результат.


Concluzie economică:
- отдельный зелёный блок;
- содержит смысл, а не только число.


Exemplu practic:
- отдельный нейтрально-серый блок;
- только после полного решения исходной задачи.

9. ЗАДАЧИ ДЛЯ СТУДЕНТОВ

Структура:
Problemă
→ Date
→ Cerințe
→ Indicații pentru rezolvare
→ Concluzie economică cerută


Cerințe — обычно 2–3 коротких расчётных пункта.
Indicații pentru rezolvare — 2–3 логических шага без подстановки чисел и без ответа.
Concluzie economică cerută — отдельный вопрос на экономическое понимание.


Решение не показывать.

ЕДИНАЯ СТРУКТУРА ПОСТРОЕНИЯ ЗАДАЧ — ОБЯЗАТЕЛЬНО ДЛЯ ВСЕГО КУРСА

A. РЕШЁННЫЕ ЗАДАЧИ


Обязательный порядок:


Problemă
→ Date
→ Cerințe
→ Indicații pentru rezolvare
→ Rezolvare
→ Concluzie economică
→ Tabel-sinteză [если результатов несколько]
→ Exemplu practic [если помогает пониманию]
→ Pentru înțelegere mai profundă [только когда это методически оправдано]


1. Problemă
- 1–2 коротких предложения: что исследуется и от каких факторов зависит результат.
- Не начинать сразу с формул.
- При первом упоминании каждого обозначения обязательно давать пояснение в скобках.
- Использовать единый типографический формат БЕЗ символа подчёркивания. Для Moodle HTML применять нижние и верхние индексы через <sub> и <sup>:
  Q<sub>d</sub>, Q<sub>s</sub>, Q<sub>d,a</sub>, P<sub>a</sub>, P<sub>b</sub>, P<sub>x</sub>, P<sub>y</sub>, E<sup>p</sup><sub>d</sub>, E<sub>i</sub>, E<sub>xy</sub>, ΔQ<sub>d</sub>% и т.д.
Для DOCX/PDF/PPTX использовать настоящие типографические нижние/верхние индексы, а не подчёркивания в тексте.


Пример:
Q<sub>d,a</sub> (cantitatea cerută din bunul A)
P<sub>b</sub> (prețul bunului B)
I (venitul consumatorilor)


2. Date
Если данных больше двух-трёх, оформлять их в таблице:
Indicator | Semnificație | Valoare / modificare


Для процентных изменений обязательно показывать направление и знак:
- scade cu 4% → ΔP% = −4%
- crește cu 5% → ΔP% = +5%


Нельзя терять знаки и нельзя заменять отрицательное изменение положительным числом без пояснения.


3. Cerințe
Cerințe должны быть короткими, конкретными и понятными без расшифровки преподавателя.


По умолчанию — 2–3 пункта, которые задают последовательность расчёта.
Связанные вычисления можно объединять в один пункт, не теряя содержания исходной задачи.


Формулировать через действие + экономический смысл, а не через список символов.


ПРАВИЛЬНО:
1. Găsiți prețul și cantitatea de echilibru.
2. Calculați elasticitatea cererii și a ofertei în punctul de echilibru.
3. Stabiliți care parte a pieței este relativ mai inelastică: cererea sau oferta.


НЕЖЕЛАТЕЛЬНО:
1. P* și Q*;
2. elasticitatea cererii;
3. elasticitatea ofertei;
4. partea relativ mai inelastică;
5. anticipați efectul impozitului...


Интерпретационные, объяснительные и прогнозные требования не перегружают Cerințe.
Их переносить в «Concluzie economică cerută».


Исключение: если это source-controlled test / assessment, где пункты должны быть сохранены дословно, исходную структуру не сокращать.


4. Indicații pentru rezolvare
Это НЕ мини-лекция и НЕ скрытое решение.


Название блока во всех семинарах использовать строго: „Indicații pentru rezolvare”.
Не использовать варианты „Ce trebuie să știți înainte să rezolvați” или „Ce trebuie să știm înainte să rezolvăm”.


Давать только 2–3 коротких опорных пункта, которые помогают студенту построить логическую последовательность решения:
1. с чего начать;
2. какую формулу / условие применить;
3. как сравнить или интерпретировать полученные показатели.


Не повторять весь теоретический раздел.
Не подставлять числа.
Не показывать промежуточный или конечный ответ.


Пример для задачи «echilibru + elasticități»:
1. Determinăm echilibrul din Q<sub>d</sub> = Q<sub>s</sub>.
2. Calculăm elasticitățile în punctul de echilibru folosind coeficienții lui P și raportul P*/Q*.
3. Comparăm valorile absolute ale coeficienților; valoarea mai mică indică partea relativ mai inelastică.


Добавлять только ту теорию, которая нужна для данной задачи.


Для задач по эластичности, в зависимости от типа:
ΔQ<sub>d</sub>% = E<sup>p</sup><sub>d</sub> × ΔP%
E = (coeficientul factorului) × (factor / Q<sub>d</sub>)
ΔQ<sub>d</sub>% ≈ E<sub>p</sub> × ΔP<sub>x</sub>% + E<sub>i</sub> × ΔI% + E<sub>xy</sub> × ΔP<sub>y</sub>%


ФОРМУЛИРОВКА КЛАССИФИКАЦИИ


Не использовать тяжёлую фразу:
„Clasificăm sensibilitatea la preț prin modulul coeficientului”.


Вместо неё писать простыми словами:
„Pentru a stabili tipul cererii, comparăm valoarea absolută a coeficientului de elasticitate cu 1.”


Если сравниваются cererea și oferta:
„Pentru a compara reacția cererii și a ofertei, comparăm valorile absolute ale coeficienților de elasticitate.”


Критерии добавлять только при необходимости:
|E<sup>p</sup><sub>d</sub>| < 1 → cerere inelastică
|E<sup>p</sup><sub>d</sub>| > 1 → cerere elastică
|E<sup>p</sup><sub>d</sub>| = 1 → elasticitate unitară


E<sub>xy</sub> > 0 → bunuri substituibile
E<sub>xy</sub> < 0 → bunuri complementare
E<sub>xy</sub> = 0 → bunuri independente


E<sub>i</sub> > 0 → bun normal
0 < E<sub>i</sub> < 1 → reacție mai puțin decât proporțională la venit
E<sub>i</sub> > 1 → reacție mai mult decât proporțională la venit
E<sub>i</sub> < 0 → bun inferior


Если есть типичная ловушка, добавлять отдельную строку:
Atenție: ...


5. Rezolvare
Каждый пункт из Cerințe решается отдельным блоком.


В каждом блоке:
a) что определяем;
b) формула;
c) подстановка;
d) вычисление;
e) итоговое число жирным;
f) одна короткая экономическая интерпретация.


Нельзя писать только:
E = −4 × P/Q


Нужно объяснить:
- откуда взялось −4;
- что такое P и Q;
- почему используется именно эта формула;
- что означает полученное значение.


Если знак важен, объяснять его словами:
„minus cu minus dă plus”.


6. Concluzie economică
- отдельный зелёный блок;
- отвечать именно на экономический смысл задачи, а не повторять Cerințe;
- формулировка должна требовать объяснения понятия, типа, связи, причины или последствия;
- если нужно, использовать рассчитанные числа как аргумент;
- не ограничиваться фразой „rezultatul este...”.


Для студенческой задачи заголовок:
„Concluzie economică cerută”.


ПРАВИЛЬНЫЕ ТИПЫ ФОРМУЛИРОВОК:
- „Explicați ce tip de cerere rezultă și ce înseamnă acesta pentru reacția cumpărătorilor la modificarea prețului.”
- „Explicați de ce elasticitatea se modifică de-a lungul aceleiași curbe liniare a cererii.”
- „Pe baza elasticităților calculate, explicați care parte a pieței ar suporta o pondere mai mare a unui impozit unitar mic și de ce.”
- „Explicați ce indică semnul elasticității încrucișate despre relația dintre bunurile X și Y.”


НЕЖЕЛАТЕЛЬНО, если это слишком общее или дублирует расчёты:
„Comparați reacția consumatorilor și explicați semnul modificării cererii.”


Главный принцип:
Cerințe = что вычислить.
Concluzie economică cerută = что экономически объяснить на основе вычислений.


7. Tabel-sinteză
Если задача содержит несколько показателей или несколько вариантов, в конце добавлять краткую таблицу:
Indicator | Valoare / Calcul | Interpretare


8. Exemplu practic
- отдельный светло-серый блок;
- только после полного решения;
- пример должен объяснять экономический смысл, а не вводить новую задачу.


9. Pentru înțelegere mai profundă
Добавлять только там, где это действительно усиливает понимание.


Для задач, где меняется цена товара и сравниваются товары по эластичности, можно дополнительно показать изменение încasărilor:
Încasările = preț × cantitate


Оценка изменения:
(1 + ΔP%) × (1 + ΔQ%)


И затем практическое правило:
- cerere elastică → reducerea prețului poate crește încasările;
- cerere inelastică → reducerea prețului poate reduce încasările.


B. ЗАДАЧИ ДЛЯ СТУДЕНТОВ — БЕЗ РЕШЕНИЙ


Используется тот же визуальный и смысловой паттерн, но без ответа:


Problemă
→ Date
→ Cerințe
→ Indicații pentru rezolvare
→ Concluzie economică cerută


Cerințe:
- обычно 2–3 коротких пункта;
- каждый пункт начинается с понятного действия: Găsiți / Calculați / Determinați / Stabiliți;
- писать словами, что именно ищется, а не оставлять только символы;
- расчётные действия остаются в Cerințe;
- объяснение экономического смысла переносится в Concluzie economică cerută.


„Indicații pentru rezolvare”:
- только 2–3 логических шага-подсказки;
- цель блока — дать студенту опорную логику решения, а не дополнительную теорию;
- можно дать формулу или правило;
- можно объяснить, что нужно сравнить;
- можно предупредить об одной типичной ошибке;
- НЕЛЬЗЯ подставлять числа;
- НЕЛЬЗЯ показывать итоговый ответ;
- НЕЛЬЗЯ фактически решать задачу за студента.


„Concluzie economică cerută”:
- один ясный вопрос на понимание;
- не дублирует Cerințe;
- просит объяснить тип, связь, причину, последствие или экономическую интерпретацию;
- если задача допускает прогноз, именно здесь можно спросить о последствиях, например о распределении налоговой нагрузки.

ОБЯЗАТЕЛЬНО ДЛЯ ВСЕХ ТЕКУЩИХ И БУДУЩИХ ТЕМ ИНДИВИДУАЛЬНЫХ РАБОТ.

17.9. ОБЯЗАТЕЛЬНЫЙ ФОРМАТ HTML ПРИ ВСТАВКЕ В РЕДАКТОР MOODLE
     (TinyMCE / activitatea „Pagină”) — ПРОВЕРЕНО 10.10.2026
======================================================================


ПРОБЛЕМА, КОТОРУЮ НЕЛЬЗЯ ПОВТОРЯТЬ:
Редактор Moodle может удалить или проигнорировать <style> и CSS из <head>.
В результате красиво оформленный автономный HTML после вставки в Moodle
превращается в обычный текст: исчезают синие заголовки, карточки, отступы,
цвета и вёрстка. Локальный просмотр .html НЕ заменяет проверку в Moodle.


ГЛАВНОЕ ПРАВИЛО:
Если HTML предназначен для ВСТАВКИ непосредственно в редактор Moodle
(„Pagină”/TinyMCE, поле Descriere, Instrucțiuni и другие HTML-поля),
создавать специальную MOODLE-ВЕРСИЮ с полностью встроенными стилями:
каждый важный контейнер, заголовок, карточка, кнопка-ссылка и текстовый
блок получает собственный атрибут style="...".
Запрещено делать отображение зависящим ТОЛЬКО от классов, <style> в
<head>, внешней таблицы CSS или внешних библиотек.


ОБЯЗАТЕЛЬНАЯ КОНСТРУКЦИЯ:
1. Вставляемый материал — фрагмент HTML внутри одного корневого <div>,
   без обязательной зависимости от <!DOCTYPE>, <html>, <head>, <body>.
   Исходный автономный файл может содержать внешнюю оболочку документа,
   но в Moodle вставлять именно содержимое страницы.
2. Визуальные свойства указывать INLINE:
   <div style="background:#123B5D;color:#FFFFFF;padding:18px ...">
   и аналогично для каждого структурного элемента.
   Сохранять цвета курса: синий #1080E4, оранжевый #FF650B,
   зелёный #3F8F1F, тёмно-синий #123B5D.
3. Для двухуровневых раскрывающихся разделов использовать нативные
   <details><summary>Seminarul N</summary> ... </details>
   и вложенные <details><summary>Tema N</summary> ... </details>.
   Заголовки семинаров — белые буквы на синем фоне, темы с номерами
   и содержимым в отдельных карточках. Не заменять эту конструкцию
   на JavaScript-аккордеон.
4. Никаких <script>, onclick, обработчиков JavaScript или внешнего JS,
   если для страницы требуется только навигация/раскрытие блоков.
   В этой форме раскрытие работает штатными средствами браузера.
   Это правило относится к обычным информационным страницам.
   Для СПЕЦИАЛЬНЫХ интерактивных учебных модулей требования раздела 7
   остаются отдельными; их работа в конкретном Moodle требует проверки.
5. Навигацию и скачивание реализовать настоящими <a href="...">.
   Внизу страницы оставлять ссылку «Descarcă șablonul PPTX» на шаблон;
   URL можно заменить вручную в Moodle. Не вставлять выдуманный URL.
6. Сохранять читабельность внутри узкой колонки Moodle и на телефоне:
   относительная ширина, перенос длинных названий, умеренные отступы,
   отсутствие горизонтального переполнения. Не рассчитывать на @media CSS,
   который редактор может удалить.
7. Для студенческих индивидуальных работ неизменно: 5 раскрывающихся
   семинаров, внутри по 3 темы (в текущей версии — 15 тем), затем
   структура слайдов, онлайн-источники и нумерованный checklist.
   Данные только электронные или явно гипотетические согласно п. 17.8.
