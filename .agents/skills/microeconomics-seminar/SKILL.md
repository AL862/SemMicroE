## Подготовка и источники
1. Определить тему, номер семинара, тип результата и границы поручения.
2. Сверить тему с Curriculum Universitar. Прочитать существующие файлы соответствующего Seminarul N и Materiale на личном Drive и относящиеся к теме сканы из папки Resurse в репозитории. Если нужно, изучить предыдущий семинар для преемственности.
3. До планирования прочитать все относящиеся к теме страницы базовых сканов Aurelia Tomșa / Seminar_N_Sursa_*.pdf: теорию, определения, примеры, задачи, таблицы, графики и разрешённые проверочные блоки. OCR помогает искать текст; значения и геометрию сверять с изображениями. Неразборчивое не угадывать.
4. Приоритет: Curriculum → основной учебник → дополнительные источники → существующие материалы → собственные объяснения. Хранить связь выбранного содержания со страницами источника. Полноту материалов GitHub проверять по манифесту; отсутствующий файл искать на Drive.
5. Сначала отдельно решить и проверить исходные задачи. Затем планировать структуру и отбирать главное.
6. В исходных заданиях сохранять коэффициенты, функции, числа, единицы, названия, переменные, подпункты, таблицы и графическую форму. Конкретное имя вроде ASEM не заменять общим словом. Новые аналогичные задачи не выдавать за дословный источник.
7. Перед завершением согласовать термины, формулы, условия, числа, периоды, единицы и экономические выводы во всех связанных файлах. Арифметику и экономическую причинность проверять отдельно от языка.

## Язык и обозначения
- В студенческих HTML не упоминать Томша, Мэнкью, названия использованных книг и происхождение отдельных заданий. Не ставить такие пометки также в заголовках, подписях, раскрывающихся ответах и HTML-комментариях. Связь с источниками и страницами хранить отдельно в рабочем реестре; библиографию подготовить отдельным файлом по поручению пользователя.
- Для расширения объяснений использовать загруженный учебник Мэнкью «Принципы экономикс», подходящие Scientific Skills и проверенные образовательные интернет-источники. Переносить понятность, последовательность и связь с повседневными решениями в собственное румынское изложение; не имитировать авторские фразы и не выдавать методические навыки за предметный источник экономических утверждений.
- Простой нормативный румынский с ă â î ș ț. Полные фразы, удобные для чтения вслух, без телеграфных сокращений и тяжёлой лексики. Голосовую расшифровку исправлять по смыслу.
- Объяснение строить так: ситуация → причина → понятие и символы → формула → короткий пример → расчёт и результат → экономическая интерпретация. Формула находится рядом с объясняемым понятием. При первом упоминании обозначения дать его смысл; на слайдах сначала полное название, затем сокращение.
- В видимом учебном тексте нет запятых. Грамматически перестраивать предложения, а не удалять обязательный знак. Аргументы функций разделять точкой с запятой. Дробные значения показывать точными обычными дробями либо словами. Это правило не относится к разделителям JS, CSS, JSON, CSV и не удаляет диакритики ș/ț.
- Не использовать «cheltuiala»: выбирать естественную замену по смыслу. Вместо «ceteris paribus» писать «ceilalți factori rămân neschimbați». Вместо «în modelul simplificat al seminarului» прямо назвать допущение.
- Основные символы Q, P, E, MU, TU, CO и т.п. — прописные обычного размера. Буквенные индексы — строчные уменьшенные. В HTML использовать sub/sup, в DOCX/PDF/PPTX — настоящие типографические индексы. Не имитировать их подчёркиваниями; технические имена кода могут содержать _.
- Формулы, подписи графиков, таблицы и динамический текст проверять по тем же правилам. В полях без форматирования применять понятные словесные обозначения.
- Учебные добавления должны быть экономически верны и не противоречить источнику. Происхождение собственных примеров фиксировать в рабочих записях. Более точные специальные условия содержатся в соответствующем навыке.

## Поведение интерактивных HTML
Для всех интерактивных учебных HTML обработчики подключать через addEventListener. Inline-обработчики вроде onclick не использовать.

## Область запретов и визуальная система
- В семинарах, преподавательских презентациях и конспектах нет studii de caz, sarcini analitice и тем рефератов, включая аналоги под другим названием. При порученном обновлении удалить такой блок и восстановить нумерацию.
- Обычные расчётные примеры и разрешённые проверочные задания сохраняются. У студенческих индивидуальных работ отдельная область действия: пользоваться их предметным навыком.
- Оформление учебного HTML определяется единым [стандартом Moodle](../microeconomics-moodle/references/design-system.md). Его параметры применяются ко всем семинарам; локальные визуальные варианты не создаются. Цветовые значения хранятся только в [реестре ресурсов](references/course-resources.md).

## Файлы и сохранение
- Текущие учебные материалы распределены по папкам [0]–[6] из реестра. HTML семинаров находятся в папке [1]. Старые корневые папки Seminarul 1–11 удалены; не создавать их заново. Исходные данные для генераторов находятся в tools/moodle-course/data.
- Сканы Томша хранятся централизованно в папке из реестра ресурсов. PDF решений остаются в семинарах. Materiale содержит структуру презентации, PPTX, DOCX-конспект и отдельные решения; Kahoot и домашнее задание добавлять только по потребности. Точные имена результатов задаёт соответствующий предметный навык.
- Папка «[1] Fișiere HTML ale cursului pentru încărcare pe Moodle» содержит копии для загрузки с именем «N. Seminarul - Titlul temei.html»: номер без ведущего нуля, Seminarul, дефис и полное название темы. Корневые папки старых семинаров после реорганизации не сохраняются. Несозданные темы не заменять пустыми HTML.
- Перед обновлением прочитать существующий файл. Обновлять его на месте; новые версии делать по необходимости. Промежуточные версии помещать в Arhiva, не создавать случайные FINAL, _v2, _v3, (1).
- Сохранять учебные результаты на личном Drive в зарегистрированном расположении с сохранением существующего ID. Запись в GitHub подтверждать отдельно; текущий запрос может ограничивать изменения только репозиторием.
- Не заявлять об успешном сохранении или проверке до реальной записи и повторного чтения. В отчёте отмечать недоступные проверки, например конечные страницы Moodle за авторизацией.
- Последовательность номеров задач, разделов, слайдов и страниц проверять после вставок и удалений. Исходные номера заданий сохраняются, если это часть структуры источника. DOCX/PDF: номер страницы внизу, последовательный со второй страницы; титул может не показывать номер.
